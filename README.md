# Brokerage Pipeline & Revenue — Python · Snowflake · Streamlit

An analytics app for a rental brokerage: CRM data is synced **incrementally** from the operational database
into **Snowflake**, and a **Streamlit** dashboard queries Snowflake for revenue, funnel, agent, market and
AI-call metrics. All aggregation runs in Snowflake; Streamlit only receives small result sets.

```
CRM DB (SQLite here, PostgreSQL in prod) ──sync.py──▶ Snowflake (MERGE on PK) ──▶ Streamlit (app.py)
        updated_at >= watermark                        BROKERAGE.ANALYTICS            cached queries
```

Data is synthetic (80k leads, ~240k calls, Chicago neighborhoods) — generated by `seed.py`.

| File | What it does |
|---|---|
| `seed.py` | Builds the source CRM; `--activity N` simulates a day of new leads + status changes |
| `sync.py` | Watermark-based incremental ELT: extract changed rows → `write_pandas` to a temp stage → `MERGE` |
| `warehouse.py` | Snowflake client (DuckDB fallback for offline dev & CI — same SQL) |
| `queries.py` | Dashboard SQL (KPIs w/ period-over-period deltas, funnel, monthly revenue, leaderboards) |
| `app.py` | Streamlit UI, cached queries, live SQL log |
| `tests/` + `.github/workflows/ci.yml` | Full pipeline + SQL tests run on every push (ruff + pytest) |

## Run it against Snowflake

1. Free trial: <https://signup.snowflake.com>. In a Snowsight worksheet run `sql/snowflake_setup.sql`.
2. Key-pair auth (no password stored anywhere):
   ```bash
   openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out ~/.snowflake/rsa_key.p8
   openssl pkey -in ~/.snowflake/rsa_key.p8 -pubout   # paste the body into:
   # ALTER USER <user> SET RSA_PUBLIC_KEY='MIIB...';
   ```
   `~/.snowflake/connections.toml` (outside the repo, `chmod 600`):
   ```toml
   [default]
   account = "<orgname>-<account_name>"
   user = "<login name>"
   authenticator = "SNOWFLAKE_JWT"
   private_key_file = "/Users/<you>/.snowflake/rsa_key.p8"
   warehouse = "ANALYTICS_WH"
   database = "BROKERAGE"
   schema = "ANALYTICS"
   ```
3. ```bash
   python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
   python seed.py          # 80k leads into data/crm.db
   python sync.py          # initial load into Snowflake
   streamlit run app.py
   ```
4. Incremental demo: `python seed.py --activity 500 && python sync.py` → only ~1,000 changed rows merge;
   click **Refresh from warehouse** in the app.

Offline mode (no Snowflake account): prefix commands with `WAREHOUSE=duckdb`.

## Deploy (Streamlit Community Cloud)

1. share.streamlit.io → **Create app** → pick this repo, branch `main`, file `app.py`, Python 3.12.
2. **Advanced settings → Secrets**: paste `.streamlit/secrets.toml.example` filled in with your values
   (the private key goes in as a multi-line string). Secrets live only in Streamlit Cloud, never in git.
3. Deploy. The app reads `[snowflake]` from secrets; locally it falls back to `~/.snowflake/connections.toml`.
